Mining Region Registry

Every contested mining region on the island, what it produces, and how much ore enters the world each session. Amounts are editable — change any number and every total, graph, and per-refill figure updates live. Built as a spec for the site build.

01How a region ID is built

Each region carries a structured ID so a region can be identified from its tag alone. Read it left to right.

1 D - diamond+iron - region-1 - corner-1
1  — count: how many regions of this primary-ore type exist
D  — primary ore letter (the region's headline resource)
diamond+iron  — full contents: every ore the region actually holds
region-1  — the region's own number
D = diamond primary I = iron primary G = gold primary M = mixed (no single primary)
A region is a cuboid box defined by two opposite corners — corner-1 and corner-2 — each an X Y Z coordinate. Both corners share the same parent Data ID (e.g. 1D-diamond+iron-region-1), which is how the plugin groups the two corners into one zone.

For the developer

This page is a spec + live calculator. The numbers a designer edits here are the ore-per-refill per region. Everything else is derived:

  • Per session = ore-per-refill × refills-per-session (global refill count, editable up top).
  • World total = sum of every region's per-session amount, per ore type.
  • The chart shows each ore's world total broken down by which region contributed it.
  • Region positions come from the midpoint of each region's two corner coordinates, mapped onto the island bounds. No team sizes or player counts are assumed anywhere — this only describes ore supply.
  • Save writes the full config (regions, coordinates, ore amounts, refill count, session length) to a JSON object — currently to localStorage as a stand-in; wire the saveConfig() function to your backend to persist it server-side.

Each region object already carries its id, both corners, the parent dataId, and its ores map. That structure is ready to hand to the plugin that places/refills the ore.
